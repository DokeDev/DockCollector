# DockCollector · Dock采集器

DockCollector 是一款本地运行、规则驱动的可视化网页采集工具。它将网站差异封装为独立采集规则，让多个目标、多个页面来源、不同账号与代理配置可以在同一套程序中分别管理。

无需为每个目标重新开发爬虫：通过可视化规则拾取器选择页面元素，再配置列表筛选、字段提取、读取频率和结束条件，即可形成可导入、可导出的采集规则。

> 请仅采集你有权访问和处理的数据，并遵守目标网站的服务条款、robots 规则及适用法律。

## 特色功能

### 可视化规则拾取

- 使用程序内置 Chromium 打开本地 HTML 或在线网页。
- 直接点击页面元素生成 CSS 选择器。
- 支持一次选择多个字段，并分别命名、增删和排序。
- 可识别列表项容器、详情链接和下一页/加载更多元素。
- 页面来源、拾取器来源和字段规则均可独立排序。
- 规则可以导出，用于迁移、备份或复用到其他环境。

### 通用的多目标采集

- 每个目标拥有独立规则、运行状态、结果和导出文件。
- 一个目标可包含多个页面来源，并按顺序逐个执行。
- 元素提取规则可以在同一目标的不同来源之间复用。
- 支持列表页过滤，在打开详情前排除不符合条件的条目。
- 支持文本字段、元素属性及链接地址提取。
- SQLite 自动记录已采集链接，减少重复读取。

### 来源级账号与代理

- 每个页面来源可以使用独立登录账号和独立浏览器配置。
- 支持在内置浏览器中手动登录并保存登录状态。
- 支持导入 Cookie，也可以完全使用手动登录。
- 支持直连、固定 HTTP/SOCKS5 代理和代理 API。
- 代理 API 支持 GET/POST、认证请求头、JSON 路径取值和失败重试。
- 来源未配置独立代理时，可继承目标级代理设置。

### 智能验证码处理

- 使用 ddddocr 在本地识别常见字符验证码。
- 支持算术验证码识别并自动计算结果。
- 支持逐字符旋转图片的增强识别。
- 支持常见滑块缺口定位和模拟拖动。
- 自动提交后，不只依赖网站提示文案，而是结合验证码组件、URL、页面内容及正常采集结构判断是否真正通过。
- 自动处理失败或状态无法确认时，暂停当前任务并开放人工操作；手动完成后自动恢复。
- 正常采集期间锁定人工页面操作，防止误点击破坏任务流程。

### 运行频率与结束控制

- 分别设置列表翻页间隔和详情读取间隔。
- 设置页面加载超时、失败重试及退避时间。
- 限制最大列表页数、最大详情数、最长运行时间和验证码次数。
- 连续空页达到指定数量后结束当前来源。
- 列表页或详情页命中指定文字时结束。
- 指定字段包含目标内容时结束。
- 所有来源处理完成后，任务状态显示为“采集完成”。

### 三种浏览器运行模式

- **可见模式**：采集过程始终显示浏览器，便于观察和调试。
- **后台静默模式**：无界面运行，适合规则稳定后的长期任务。
- **自动切换模式**：正常采集时最小化，遇到验证码时自动恢复窗口。

### 可视化状态与独立导出

- 控制台实时展示运行状态、列表页数、打开数、保存数和验证码次数。
- 显示当前来源、当前页面和正在执行的动作。
- 每个目标独立查看采集结果与事件日志。
- 支持按目标导出 CSV。
- 支持导出完整采集规则。

## 快速开始

### Windows

1. 安装 Python 3.10 或更高版本，并勾选 **Add Python to PATH**。
2. 下载或克隆本项目。
3. 双击 `启动Dock采集器.bat`。

首次运行时，启动器会自动创建 `.venv-windows`、安装 Python 依赖并下载程序内置 Chromium。准备完成后会自动打开：

<http://127.0.0.1:3780>

### macOS

安装 Python 3.10 或更高版本后，双击 `启动Dock采集器.command`。首次运行时，启动器会创建独立的 `.venv-macos` 环境，在其中更新 pip、安装兼容版本的 Python 依赖和程序内置 Chromium；准备完成后自动打开控制台。首次安装需要联网，后续可直接启动。也可以在终端中运行该文件；按 `Control+C` 停止服务。

### 命令行启动

完成依赖与 Chromium 安装后，可直接运行：

```bash
python3 run.py
```

然后访问 <http://127.0.0.1:3780>。

## 使用流程

1. 点击左侧“新建目标”，填写目标名称、标识、目录和域名。
2. 在“页面来源”中添加一个或多个列表页地址，并调整执行顺序。
3. 打开“账号/代理”，为每个来源完成预登录，并按需设置独立代理。
4. 在“列表筛选”中识别或填写列表项、详情链接、下一页选择器和必含文字。
5. 在“字段提取”中打开可视化规则拾取器，点击需要保存的页面元素。
6. 在“频率与结束”中设置读取间隔、读取上限和结束条件。
7. 选择可见、静默或自动切换运行模式，保存设置后开始运行。
8. 在“采集结果”中检查数据并导出 CSV；需要迁移时使用“导出规则”。

## 列表过滤示例

如果“必含文字”设置为 `昨天`，DockCollector 会先检查列表项所在容器：

- 列表项包含“昨天”：打开详情并采集。
- 列表项不包含“昨天”：直接略过，不打开详情页。
- 详情页正文中出现“昨天”：不影响列表过滤结果。

这种方式可以减少无效详情请求，也避免把详情页字段误当作列表时间条件。

## 规则组成

每个目标规则主要包含：

| 规则区域 | 用途 |
| --- | --- |
| 页面来源 | 列表页地址、执行顺序、来源账号和独立代理 |
| 列表筛选 | 列表项容器、详情链接、下一页和必含文字 |
| 字段提取 | 字段名称、提取方式、CSS 选择器、属性及清理规则 |
| 频率与结束 | 请求间隔、读取上限、空页、文字及字段结束条件 |
| 运行模式 | 可见、后台静默或自动切换 |
| 代理与验证码 | 目标级代理、代理 API、验证码检测及自动尝试次数 |

## 数据与目录

- `collector.db`：目标配置、采集结果、去重记录和事件日志。
- `<目标目录>/浏览器数据/`：各页面来源的浏览器配置和登录状态。
- `.browsers/`：macOS 使用的程序内置 Chromium。
- `.browsers-windows/`：Windows 使用的程序内置 Chromium。
- `.venv-macos/`：macOS 独立 Python 环境。
- `.vendor/`：旧版 macOS 启动方式使用的兼容依赖目录。
- `.venv-windows/`：Windows 独立 Python 环境。

删除目标时，数据库中的目标配置和结果会被删除，目标目录默认保留，便于用户自行确认后处理其中的浏览器登录状态或其他文件。

- ddddocr
- 原生 HTML、CSS 与 JavaScript

## 当前定位

DockCollector 面向需要长期维护多个网页采集目标的本地工作流。重点不是为单一网站写死逻辑，而是将页面来源、登录环境、网络出口、元素提取、运行节奏、验证码处理和结束策略组合成可视化规则，使新增目标时尽可能只需配置，而不必修改程序代码。
