# DockCollector · Dock采集器

DockCollector 是一款本地运行、规则驱动的可视化网页采集工具。它将网站差异封装为独立采集规则，让多个目标、多个数据列表、不同账号与代理配置可以在同一套程序中分别管理。

无需为每个目标重新开发爬虫：通过可视化规则拾取器选择页面元素，再配置列表筛选、字段提取、读取频率和结束条件，即可形成可导入、可导出的采集规则。

> 请仅采集你有权访问和处理的数据，并遵守目标网站的服务条款、robots 规则及适用法律。

## 特色功能

### 可视化规则拾取

- 在字段提取中填写“内容页网址”，使用程序内置 Chromium 直接打开内容页。
- 打开在线网页时可选择统一账号或数据列表独立账号，并沿用对应登录状态与代理。
- 直接点击页面元素生成 CSS 选择器。
- 支持一次选择多个字段，并分别命名、增删和排序。
- 可自动识别列表项容器、详情链接、列表时间和下一页/加载更多元素，确认后直接保存规则。
- 手动修正会预载已保存的四项列表规则，只需重选不准确的项目。
- 自动识别和手动修正都可选择统一账号、独立账号或游客状态。
- 数据列表和字段规则均可独立排序。
- 规则可以导出，用于迁移、备份或复用到其他环境。

### 通用的多目标采集

- 每个目标拥有独立规则、运行状态、结果和导出文件。
- 一个目标可包含多个数据列表，并按顺序逐个执行。
- 元素提取规则可以在同一目标的不同数据列表之间复用。
- 支持列表页过滤，在打开详情前排除不符合条件的条目。
- 列表过滤可在列表项内部可视化选择标题、作者或分类等具体元素，并配置包含、等于、不包含、出现、消失或为空；命中后只跳过当前记录，不会结束数据列表或整个任务。
- 每个提取字段可配置“字段包含即不采集”，命中后整条详情不写入结果。
- 同时支持下一页按钮和滚动到底加载的瀑布流列表。
- 支持文本字段、元素属性及链接地址提取。
- SQLite 自动记录已采集链接，减少重复读取。

### 数据列表级账号与代理

- 支持统一账号、来源独立账号和混合三种策略。
- 统一账号可供目标下所有数据列表共用，只需预登录一次。
- 统一账号且代理一致的数据列表会复用同一个 Chromium 进程连续采集，减少反复启动和缓存预热时间。
- 混合模式默认继承统一账号，个别数据列表可切换为独立账号。
- 每个数据列表也可以使用独立登录账号和独立浏览器配置。
- 支持在内置浏览器中手动登录并保存登录状态。
- 支持导入 Cookie，也可以完全使用手动登录。
- 支持直连、固定 HTTP/SOCKS5 代理和代理 API。
- 代理 API 支持 GET/POST、认证请求头、JSON 路径取值和失败重试。
- 数据列表未配置独立代理时，可继承目标级代理设置。

### 智能验证码处理

- 使用 ddddocr 在本地识别常见字符验证码。
- 支持算术验证码识别并自动计算结果。
- 支持逐字符旋转图片的增强识别。
- 支持常见滑块缺口定位和模拟拖动。
- 自动提交后，不只依赖网站提示文案，而是结合验证码组件、URL、页面内容及正常采集结构判断是否真正通过。
- 内置常见中英文验证文案及 reCAPTCHA、hCaptcha、Cloudflare Turnstile、GeeTest 等组件特征，并允许按目标补充。
- 以最近正常详情页建立运行时页面指纹；正文长度或字段结构突然异常时复核并阻止空数据入库。
- 自动处理失败或状态无法确认时，暂停当前任务并开放人工操作；手动完成后自动恢复。
- 验证后必须重新检测到正常详情结构才允许保存，避免把验证页写成全空结果。
- 正常采集期间锁定人工页面操作，防止误点击破坏任务流程。

### 运行频率与结束控制

- 分别设置列表翻页间隔和详情读取间隔。
- 设置页面加载超时、失败重试及退避时间。
- 限制最大列表页数、最大详情数、最长运行时间和验证码次数。
- 连续空页达到指定数量后结束当前数据列表。
- 使用统一的可视化停止条件管理多条结束规则。
- 判断对象支持已提取字段、页面元素和页面全文。
- 判断方式支持包含、等于、不包含、出现、消失和内容为空。
- 页面元素停止条件可使用已登录账号或游客状态打开浏览器点击生成。
- 每条条件可选择停止当前数据列表或停止整个目标；多条启用条件任意一条命中即执行。
- 所有数据列表处理完成后，任务状态显示为“采集完成”。

### 三种浏览器运行模式

- **可见模式**：采集过程始终显示浏览器，便于观察和调试。
- **后台静默模式**：使用临时无界面上下文并导入已保存 Cookie，不读取 Chromium 持久化钥匙串，适合规则稳定后的长期任务。
- **自动切换模式**：正常采集时最小化，遇到验证码时自动恢复窗口。

### 可视化状态与独立导出

- 控制台实时展示运行状态、列表页数、打开数、保存数和验证码次数。
- 显示当前数据列表、当前页面和正在执行的动作。
- 每个目标独立查看采集结果与事件日志。
- 采集结果页面每 1.5 秒自动检查新增数据，无需手动刷新。
- 支持暂停、继续，以及安全停止后清空结果并从第一条数据列表重新开始。
- 支持修改目标显示名称，且不改变目标 ID、目录、规则、账号或历史结果关联。
- 支持按目标导出 CSV。
- 支持导出完整采集规则。

## 快速开始

### Windows

1. 安装 Python 3.10 或更高版本，并勾选 **Add Python to PATH**。
2. 下载或克隆本项目。
3. 双击 `启动Dock采集器.bat`。

首次运行时，启动器会自动创建 `.venv-windows`、安装 Python 依赖并下载程序内置 Chromium。准备完成后会自动打开：

<http://127.0.0.1:3780>

### macOS

安装 Python 3.10 或更高版本后，双击 `启动Dock采集器.command`。首次运行时，启动器会创建独立的 `.venv-macos` 环境，在其中更新 pip、安装兼容版本的 Python 依赖和程序内置 Chromium；准备完成后自动打开控制台。首次安装需要联网，后续可直接启动。也可以在终端中运行该文件；按 `Control+C` 停止服务。

### 命令行启动

完成依赖与 Chromium 安装后，可直接运行：

```bash
python3 run.py
```

然后访问 <http://127.0.0.1:3780>。

## 使用流程

1. 点击左侧“新建目标”，填写目标名称、标识、目录和域名。
2. 在“数据列表”中添加一个或多个列表页地址，并调整执行顺序。
3. 打开“账号/代理”，为每个数据列表完成预登录，并按需设置独立代理。
4. 在“列表筛选”中识别或填写列表项、详情链接、列表时间、下一页选择器和时间必含文字；需要排除记录时，可选择数据列表与浏览器账号，点击“打开浏览器 · 新增过滤规则”，再点击标题、作者或分类等判断元素。
5. 在“字段提取”中填写内容页网址、选择浏览器账号并打开可视化规则拾取器，点击需要保存的页面元素。
6. 在“频率与结束”中设置读取间隔、读取上限，并按需增加字段、页面元素或页面全文停止条件。
7. 选择可见、静默或自动切换运行模式，保存设置后开始运行。
8. 在“采集结果”中检查数据并导出 CSV；需要迁移时使用“导出规则”。

## 列表过滤示例

如果“列表时间”定位到的元素显示 `昨天 11:51`，并将“时间必须包含的文本”设置为 `昨天`：

- 时间元素包含“昨天”：打开详情并采集。
- 时间元素不包含“昨天”：直接略过，不打开详情页。
- 详情页正文中出现“昨天”：不影响列表过滤结果。
- 同一列表项的其他位置出现“昨天”：不影响列表过滤结果。

匹配方式是“包含”而不是“完全相等”。例如时间显示 `4 天前`，条件填写 `天前` 即可匹配。

这种方式可以减少无效详情请求，也避免把最后回复时间或其他字段误当作发布时间。

## 规则组成

每个目标规则主要包含：

| 规则区域 | 用途 |
| --- | --- |
| 数据列表 | 数据列表页地址、执行顺序、登录账号和独立代理 |
| 列表筛选 | 列表项容器、详情链接、列表时间、下一页、时间必含文字和元素级过滤规则 |
| 字段提取 | 字段名称、提取方式、CSS 选择器、属性及清理规则 |
| 频率与结束 | 请求间隔、读取上限、空页和可视化停止条件 |
| 运行模式 | 可见、后台静默或自动切换 |
| 代理和打码 | 目标级代理、代理 API、验证码检测、自动识别及人工回退 |

## 数据与目录

- `collector.db`：目标配置、采集结果、去重记录和事件日志。
- `<目标目录>/浏览器数据/`：各数据列表的浏览器配置和登录状态。
- `.browsers/`：macOS 使用的程序内置 Chromium。
- `.browsers-windows/`：Windows 使用的程序内置 Chromium。
- `.venv-macos/`：macOS 独立 Python 环境。
- `.vendor/`：旧版 macOS 启动方式使用的兼容依赖目录。
- `.venv-windows/`：Windows 独立 Python 环境。

删除目标时，数据库中的目标配置和结果会被删除，目标目录默认保留，便于用户自行确认后处理其中的浏览器登录状态或其他文件。

## 当前定位

DockCollector 面向需要长期维护多个网页采集目标的本地工作流。重点不是为单一网站写死逻辑，而是将数据列表、登录环境、网络出口、元素提取、运行节奏、验证码处理和结束策略组合成可视化规则，使新增目标时尽可能只需配置，而不必修改程序代码。
